### ✅ 2.1 `reorder-line` → per-device transient

- `store.ts`: new state field `lineOrderOverride: Record<TeamId, PlayerId[]>` (initial `{ A: [], B: [] }`). Added to `partialize` and reset in `resetAllData`.
- `store.ts`: new exported helper `applyLineOverride(engineLine, override)` — gracefully degrades stale overrides (filters out ids no longer on the field, appends new arrivals in engine order).
- `store.ts`: `reorderActiveLine` and `swapLineSlots` rewritten — no longer append `reorder-line` events; they compute the effective order from `engineLine + lineOrderOverride`, apply the swap/move, and store the result on `lineOrderOverride`.
- `engine.ts`: `step` case for `reorder-line` is now a documented no-op (legacy compat for any persisted rawLogs that still carry these events).
- `engine.ts`: `resolveRawLog` always filters `reorder-line`; `keepReorderLine` flag and `ResolveOpts` interface removed (no callers care). `applySplice` filters `reorder-line` unconditionally too.
- `engine.ts`: `resolveLogForDerivation` kept as a named alias of `computeVisLog`'s walker (produces same output now; name preserved for call-site readability).
- `LiveEntry/index.tsx`: imports `applyLineOverride`; subscribes to `s.lineOrderOverride`; reorders `activePlayers` per the override before passing to Stage.
- `store.test.ts`: swapLineSlots tests rewritten — asserts the override updates and the rawLog is unchanged.
